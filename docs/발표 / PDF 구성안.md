# 발표 / PDF 구성안 (10~12장)

1. **표지**: LoginGuard AI - 비밀번호를 까먹는 사람들을 위한 AI 로그인 보안 서비스

2. **문제 정의**
   - 최근 잦은 개인정보·계정 유출 사고
   - 까먹으니까 → 쉬운 비밀번호 + 재사용 → 한 곳 유출 시 연쇄 피해(크리덴셜 스터핑)

3. **해결 아이디어**: "기억하기 쉬운 강한 비밀번호를 만들게 돕고, 유출돼도 막는다"
   - ① 진단 → ② 코칭 → ③ 2차 인증 흐름 그림

4. **전체 구조도**
   ```
   사용자 ─▶ Gradio 웹앱 ─┬▶ ① BiLSTM 위험도 모델 ─▶ 진단 결과(원문 제외) ─▶ ② LLM 코치
                         └▶ ③ 키 입력 시간 수집(JS) ─▶ 31개 특징 ─▶ 오토인코더 ─▶ 통과/차단 ─▶ ② LLM 알림
   ```

5. **① 비밀번호 위험도 진단**
   - 데이터: 흔한 비밀번호 유형 + 변형 규칙으로 합성 (실제 유출 DB 미사용 → 개인정보 보호)
   - 모델: 문자 임베딩 → BiLSTM → 위험 확률
   - 결과: 정확도, F1, 혼동행렬 (`reports/password_confusion.png`)
   - 포인트: 평가 데이터는 학습 때 안 본 단어로 생성 → 일반화 확인

6. **② LLM 보안 코치**
   - Gemini 무료 API, 장애 시 Groq → 오프라인 안내문 자동 전환
   - **비밀번호 원문은 LLM에 보내지 않음** (진단 결과만 전달)
   - 프롬프트 예시와 실제 답변 캡처

7. **③ 타이핑 패턴 2차 인증**
   - 데이터: CMU Keystroke Benchmark (51명 × 400회)
   - 특징: 누른 시간(H), 키 간 간격(DD, UD) 31개
   - 모델: 본인 입력만으로 학습하는 디노이징 오토인코더 → 복원 오차가 크면 타인
   - 결과: 평균 EER, Manhattan 기준모델·논문 수치(9.6~10.2%)와 비교 (`reports/keystroke_eer.png`)

8. **시연 화면** (탭별 캡처 또는 영상)
   - `123456` 위험 → 코치 → 문장형 비밀번호 안전
   - 본인 로그인 통과 / 타인 로그인 차단 + LLM 알림

9. **개인정보 보호 설계**
   - 비밀번호 원문 외부 전송 없음, 유출 DB 미사용, 타이핑 특징은 숫자 31개만 사용

10. **한계와 향후 계획**
    - 합성 데이터 한계 → 공개 비밀번호 강도 연구 데이터로 확장
    - 사용자 비밀번호 기반 등록, 마우스 패턴·얼굴 인증으로 확장
    - PickMe 등 실제 서비스 로그인에 연동

11. **기대효과**: 계정 탈취 예방, 비밀번호 재사용 감소, 쉬운 사용성
